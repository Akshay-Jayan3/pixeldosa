---
title: Field
description: A composable form-field wrapper — Field, FieldLabel, FieldControl, FieldDescription and FieldError — that wires ARIA automatically onto whatever control you place inside it.
---

## Usage

```tsx
import { Field, FieldControl, FieldDescription, FieldError, FieldLabel } from "@/components/ui/field";

export function EmailField({ value, onChange, error }: Props) {
  return (
    <Field invalid={Boolean(error)}>
      <FieldLabel>Email</FieldLabel>
      <FieldControl>
        <input type="email" value={value} onChange={onChange} className="…" />
      </FieldControl>
      <FieldDescription>We'll only use this to send order updates.</FieldDescription>
      <FieldError>{error}</FieldError>
    </Field>
  );
}
```

`FieldControl` clones its single child, so it accepts exactly one React element — a
native `<input>`/`<textarea>`, or any component that forwards `id`, `aria-invalid`,
`aria-describedby` and `ref` to a real form control.

`FieldError` renders nothing when its children are falsy, so you can pass a validation
message straight through without a conditional wrapper.

## Features

- **ARIA wiring you never write by hand**: the control receives `id`,
  `aria-invalid` and a composed `aria-describedby` pointing at whichever of the
  description and error are actually present.
- **Bring your own control** — `FieldControl` clones its single child, so it works
  with a native `<input>`/`<textarea>` or any component that forwards `id`, `ref`
  and the ARIA attributes to a real form control.
- **`FieldError` renders nothing when falsy**, so a validation message can be passed
  straight through without a conditional wrapper around it.
- **Announced late errors**: `role="alert"` means an async validation message is read
  out even when the field already has focus.

### Invalid

`invalid` flows into `aria-invalid` on the control, which the input styling hooks with
`aria-invalid:` variants — the ring is a consequence of the ARIA state, not a parallel
visual flag that can drift out of sync with it.

<PreviewStack>
  <Field invalid className="w-full max-w-sm">
    <FieldLabel>Email</FieldLabel>
    <FieldControl>
      <input
        type="email"
        defaultValue="hello@"
        aria-invalid
        className="h-9 w-full rounded-md border border-input bg-transparent px-3 text-sm aria-invalid:border-destructive"
      />
    </FieldControl>
    <FieldError>Enter a complete email address.</FieldError>
  </Field>
</PreviewStack>

## Props

### Field

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `id` | `string` | generated | Base id for the control. Descendants derive `-description` and `-error` ids from it. |
| `invalid` | `boolean` | `false` | Marks the field invalid — flows into `aria-invalid` on the control. |

### FieldControl

Takes exactly one child element. No other props.

### FieldLabel, FieldDescription, FieldError

Standard `label` / `p` / `p` props. Must be rendered inside a `Field`.

## Accessibility

- The control receives `aria-describedby` combining the error and description ids
  automatically — you never write that string by hand.
- `FieldError` uses `role="alert"` so a message appearing after the field already has
  focus (e.g. from async validation) is still announced.
- `aria-invalid` is set on the control whenever `Field`'s `invalid` prop is true, which
  most input styling (including this system's) hooks with `aria-invalid:` variants.
