title: Agent Plan
description: The agent's plan laid out for agreement before anything runs — reorder, remove, or add a step, then run it as edited.
---

## Usage

```tsx
"use client";

import { AgentPlan } from "@/components/ui/agent-plan";

<AgentPlan
  steps={[
    { id: "1", title: "Pull the 5 flagged invoices" },
    { id: "2", title: "Match them against the August import", detail: "Reads ledger/august-import.json" },
    { id: "3", title: "Email the summary to finance@acme.com", needsApproval: true },
  ]}
  onRun={(steps) => execute(steps)}
  onCancel={() => close()}
/>
```

## Why it exists

A plan is where an agent's misunderstanding becomes visible while it's still free to
fix. Once execution starts, a wrong step costs a tool call, a side effect, or a cancel
and restart. **This is the agreement**, and then the record of what happened: give the
steps a `status` and the same component follows the run, so people watch the plan they
agreed to rather than a separate progress bar.

## Features

- **Reorder, remove, add.** Explicit up and down buttons rather than drag, so it works
  the same by keyboard, touch and mouse. Every edit is announced.
- **Removal is reversible.** A removed step stays in place, struck through, with Undo —
  never silently deleted.
- **You know where it will pause.** Steps with external effects are labelled "Asks for
  approval", and the header counts them.
- **Edits are visible.** "Run edited plan" once anything changed; steps you added are
  marked "Added by you".
- **Holds still** — it's your turn.
- **It follows the run.** Once any step has a `status`, editing stops and the plan shows
  progress: the running step is marked and moves, a step waiting on you holds still in the
  waiting colour, finished steps get a check, and a failed step offers Retry.
- **Progress is counted, never invented.** The bar measures finished steps out of the
  total, and Stop stays visible for the whole run.

## Examples

Mark every step with an external effect, so the user sees the pauses before running:

```tsx
const steps = agentPlan.map((step) => ({
  ...step,
  needsApproval: ["send_email", "update_record", "charge"].includes(step.tool),
}));
```

A fixed plan the user can trim and reorder but not extend:

```tsx
<AgentPlan steps={steps} allowAdd={false} onRun={execute} />
```

### Running the plan

Pass the same steps back with a `status` on each as the run moves. `pending` keeps a step
quiet, `running` marks the current one, `waiting` means it needs you, and `done`,
`failed` or `skipped` close it out. `note` explains a wait, a failure or a skip.

```tsx
<AgentPlan
  steps={steps.map((step) => ({ ...step, status: run.status[step.id], note: run.note[step.id] }))}
  runStatus="Reading pricing pages"
  onRun={start}
  onStop={run.abort}
  onRetryStep={run.retry}
/>
```

## Props

| Prop | Type | Description |
| --- | --- | --- |
| `steps` | `{ id, title, detail?, needsApproval?, status?, note? }[]` | Required. The proposed plan, in order. A `status` on any step switches the component to its running view. |
| `onRun` | `(steps) => void` | Required. Receives the plan as edited. |
| `onCancel` | `() => void` | |
| `title` | `string` | Defaults to `"Proposed plan"`. |
| `allowAdd` | `boolean` | Defaults to `true`. |
| `runStatus` | `string` | What's happening right now, shown beside the progress count while running. |
| `onStop` | `() => void` | Shown throughout the run. |
| `onRetryStep` | `(stepId) => void` | Offered on a failed step. |
| `headingLevel` | `2 \| 3 \| 4 \| 5 \| 6` | Heading level, so the component fits your page's outline. Defaults to `3`. |

## Accessibility

- An ordered list inside a labelled `<section>`.
- Each step's controls are a labelled group; every icon button names the step it acts on
  ("Move 'Check billing contacts' up").
- Moves, removals and additions are announced — including the new position, counting only
  steps that remain.
- While running, each step is announced once as it finishes, fails, is skipped or starts
  waiting on you. A status that hasn't changed never speaks again. The current step carries
  `aria-current="step"`, and every state is in words, not colour alone.
- Icon buttons have a 44px tall hit area, expanded vertically only, so neighbouring
  controls don't overlap.

## When not to use

Confirming what the agent understood before there's a plan is `Intent Preview`. For the
approval itself when a step stops for one, use `AI Approval Gate` beside this component:
the plan says a step is waiting, the gate states the consequence and takes the decision.
